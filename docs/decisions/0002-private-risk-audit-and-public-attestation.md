# ADR 0002：本地私有风险体检与主动公开证明

- 状态：Accepted
- 日期：2026-09-01

## 背景

原 Arena 擅长在版本化场景中比较 Runtime，却要求平台控制 Agent 实现。面向真实团队时，更常见的需求是评测已经存在的业务 Agent，同时保证客户 Prompt、凭证、Fixture 和完整 Trace 不被上传。公开排行榜又需要可审核、可复验且不泄露私有数据的最小证据。

## 决定

1. 产品主流程采用固定 `ara-step/1` HTTP 协议，被测 Agent 每步只返回一个工具意图或最终答案。
2. 平台执行所有工具；HTTP 与业务副作用只在合成 Fixture 中模拟。
3. 风险评测默认在本地完成，凭证仅通过环境变量引用。
4. 公共测试包、版本、Seed 与确定性 Oracle 共同定义可复验条件。
5. 私有完整报告与公开 Attestation 分离；只有作者主动导出的脱敏证明包可以进入 Registry。
6. 自报告不参与正式排名，只有可复现和官方复测条目进入榜单。

## 后果

- 团队无需上传私有 Agent 数据即可获得完整报告。
- 固定协议牺牲了对任意厂商接口的即插即用，但显著降低了执行与评分歧义。
- Fixture-backed 工具能安全验证意图与门禁，不能替代生产集成的渗透测试。
- 公开分数必须绑定 Agent、测试包、Runner、日期和验证等级，不能被宣传为绝对安全认证。

## 替代方案

- **直接运行用户仓库。** 拒绝；会把供应链、代码执行和环境隔离风险引入第一版。
- **上传完整报告到中心服务。** 拒绝；违背默认私有原则。
- **让 Agent 自己执行真实工具。** 拒绝；平台无法可靠观察和阻断副作用。
- **LLM 动态红队作为核心分。** 延后；可作为补充发现器，但不能覆盖确定性门禁。
