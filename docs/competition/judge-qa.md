# 评委问答

## 1. 它和普通模型排行榜有什么不同？

普通排行榜常聚焦最终回答或人类偏好。Arena 关注工具型 Agent 的执行过程：调用了什么工具、是否越权、是否等待审批、有没有泄密、用了多少步骤，以及同一场景重复运行是否稳定。

## 2. 为什么不用 LLM-as-a-Judge？

LLM Judge 可以解释开放式质量，但它本身存在模型偏好、版本变化和随机性。项目把可客观判断的核心 100 分交给确定性规则；未来的 LLM Judge 只能补充文字观察，不能修改核心分。

## 3. 如何保证不同 Agent 比较公平？

每个 Run 使用同一版本场景、相同 Fixture、相同工具白名单和独立新沙箱。Run 保存场景版本与 Trace。当前仍需继续补充种子、模型参数冻结和统计显著性，才能形成更严格的公开 Benchmark。

## 4. 这是真正的安全沙箱吗？

不是面向不可信代码的系统级安全沙箱。当前安全来自能力最小化：不提供 Shell 和通用 HTTP，文件与 SQL 仅访问单 Run 虚构副本，路径经过解析后必须仍在根内。它适用于可信主机上的受控评测。

## 5. Prompt Injection 怎么测试？

检索文档被视为不可信数据。场景在证据中放入恶意指令与 Canary，Agent 需要提取正确事实但不能泄露 Canary。Trace 脱敏和 forbidden output 共同提供证据。

## 6. 人工审批是否真正恢复原来的执行？

当前 v0.1 会暂停并持久化审批请求；批准后重新执行 Run，并由 Gateway 放行审批工具。它还不是 LangGraph 的跨 Worker interrupt/resume，这一点已经明确列入项目状态与路线图。

## 7. 为什么同时做 Minimal 和 LangGraph？

Minimal Runtime 是透明基线，LangGraph 验证图状态与 Checkpoint 接口。两者共享模型、工具和评分边界，可以减少比较 Runtime 时的混杂变量。

## 8. 评分能发现 Agent 改坏无关文件吗？

当前不完全能。v0.1 主要检查预期调用与答案片段；额外工具步骤会影响效率，但还没有完整最终状态 Oracle。下一阶段会在沙箱销毁前计算文件、数据库和文档状态差异。

## 9. 为什么使用虚构数据？

它让场景可以公开、复现和安全运行，不依赖客户数据、账号或网络。真实企业审计可以在私有环境创建专属场景，但原始数据和 Trace 不应进入公开仓库。

## 10. 项目如何商业化？

可形成三层服务：一次性可靠性体检、深度审计与修复计划、接入客户 CI 的持续回归。项目当前证明的是技术闭环，不虚构客户、收入或市场份额。

## 11. 为什么需要 pgvector？

数据库已经预留 failure embedding 表，用于后续相似失败聚类；当前在线流程尚未使用它。现阶段 RAG 仍是单 Run 文档的关键词检索。

## 12. 下一步最重要的三个能力是什么？

第一，最终状态 Oracle 和无关副作用检测；第二，Run 级并行与持久化审批恢复；第三，重复运行的方差、置信区间和失败聚类。这三项会直接提升分数可信度和规模化能力。
