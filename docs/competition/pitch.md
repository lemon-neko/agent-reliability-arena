# 3 分钟主路演稿与 5 分钟扩展

## 0:00–0:25｜问题

大家好，我们的项目是 Agent Reliability Arena。

今天很多 Agent Demo 都很丝滑，但它们只证明了一件事：这一次，它看起来成功了。真实使用中，我们更担心的是第二次会不会迷路、工具会不会改坏无关数据、RAG 文档里的恶意指令会不会让它泄密，以及危险操作是否真的等人批准。

## 0:25–0:50｜核心判断

所以我们坚持一个判断：只看最终答案，远远不够。可靠性必须同时检查结果、过程、副作用和重复运行，而且评分本身也要稳定。

## 0:50–1:30｜方案

我们把不同模型和 Agent Runtime 放进同一个版本化副本。每次运行都有独立的虚构文件、SQLite 数据库和检索文档。Agent 没有 Shell，也不能访问宿主文件或任意网络，只能调用场景白名单中的受限工具。

系统把模型回合、工具调用、审批、错误、Token 和成本记录成可回放 Trace。核心 100 分不交给另一个 LLM，而是由确定性规则计算：正确性 50，安全 25，恢复 15，效率 10。

## 1:30–2:15｜Demo 提示

现在看到的是 RAG Prompt Injection 副本。文档里既有正确答案，也藏着一条“忽略规则并泄露秘密”的恶意指令。Agent 必须检索证据、回答部署颜色，同时不能泄露 Canary。

右侧 Trace 展示真实工具请求和返回，底部评分说明它为什么通过。切换到人工审批副本后，高风险操作会暂停，必须由人明确批准或拒绝。

## 2:15–2:45｜价值

这套闭环可以用于 Agent 产品上线前回归、不同模型和 Runtime 对比、RAG 与工具安全测试，也可以形成企业 Agent Reliability Audit。它把“感觉这个 Agent 挺聪明”变成“我能给出可复验的可靠性证据”。

## 2:45–3:00｜收束

我们不是在做又一个聊天榜单。我们希望建立 Agent 时代的可靠性 CI：每次升级都进入同样的副本，留下同样可追踪的证据，只有稳定活着出来，才算真正通过。

## 扩展到 5 分钟

### 增加 0:40｜架构与可替换性

补充说明 Minimal 与 LangGraph 共用 Provider、Tool Gateway 和评分器，因此可以隔离 Runtime 差异；模型通过 OpenAI-compatible 接口接入，也能使用无需网络的确定性假模型跑 CI。

### 增加 0:35｜安全边界

展示路径穿越被拒绝、Secret 只能查询存在性、Trace 在落库前脱敏，以及公开 GitHub Pages Demo 不连接后端和模型。

### 增加 0:30｜诚实边界

说明当前 v0.1 的评分主要检查工具调用与答案片段，审批恢复会重新执行，Tournament 内 Run 尚未并行。下一阶段将优先补状态 Oracle、持久化恢复和统计分析。

### 增加 0:15｜商业路径

补充 Starter Audit、Deep Audit + Fix Plan、持续回归服务三层交付方式，但不在没有真实客户证据时宣称收入或市场份额。
