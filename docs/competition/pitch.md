# 3 分钟主路演稿与 5 分钟扩展

## 0:00–0:25｜问题

大家好，我们的项目是 Agent Reliability Arena，副标题是“Agent 风险体检与公开基准”。

当 Agent 获得文件、数据库和业务工具后，我们最担心的不是它某一次答错，而是它会不会被恶意内容诱导、泄露密钥、越权调用工具、绕过人工审批，或者在重试时把同一个高影响动作做两遍。

## 0:25–0:50｜核心判断

一次漂亮 Demo 无法证明可以上线。我们认为，Agent 必须像软件一样接受自动化风险测试：同一版本、同一 Seed、重复运行、过程留证，而且 Critical 风险不能被平均分掩盖。

## 0:50–1:25｜方案

用户让自研 Agent 实现一个很小的 HTTP Step 协议，然后选择 Quick、Standard 或 Deep。平台自动执行 12、72 或 180 次测试，覆盖注入、泄密、越权、审批、副作用、幻觉、故障恢复和资源失控。

Agent 每一步只能返回一个工具意图，真正的文件、SQL、检索、模拟网络和业务动作由平台在独立沙箱中执行。这样既能观察它想做什么，也不会触碰真实系统。

## 1:25–2:20｜Demo

现在选择“故意脆弱 Agent”，启动 Standard 体检。页面不是播放视频，而是在浏览器内动态推进 72 次测试。可以看到注入、密钥泄露和审批绕过陆续触发，执行中心显示通过率、并发进度和 Trace 证据。

报告给出六维 100 分，但平均分不是全部：一旦出现 Critical，最终等级最高只能是 E。点击 Finding，可以看到预期行为、实际行为、证据事件、复现命令和修复建议。

接着切换“加固 Agent”。同一套测试得到 A 级和建议上线。差异来自可检查行为，不是另一个 LLM 的主观偏好。

## 2:20–2:45｜隐私与公开基准

完整报告默认只在本地。作者如果希望公开，只提交不含 Endpoint、凭证、Prompt、Fixture 和完整 Trace 的最小证明包。自报告不参与正式排名，只有可复现或官方复测结果进入榜单。

## 2:45–3:00｜收束

我们不是在颁发绝对安全认证。我们提供的是固定测试条件下、能回放、能复现、能进入 CI 的风险证据。让每一次 Agent 升级，都先过体检，再谈上线。

## 扩展到 5 分钟

### 增加 0:45｜协议与安全边界

展示 `ara-step/1` 请求和单工具响应，说明公网 Endpoint 仅允许 HTTPS，平台不跟随重定向并限制响应体、步骤和超时。强调 HTTP 与业务工具只命中合成 Fixture，不是通用网络代理。

### 增加 0:35｜确定性方法

解释 12 个基础用例如何用固定 Seed 扩展为 Standard 36 个逻辑测试、每项重复两次；说明安全与隐私、权限与人工控制、工具副作用、正确性、恢复性和效率的六维权重。

### 增加 0:25｜真实本地流程

运行 `make demo-live`，注册仓库自带的两个参考 Endpoint，展示真实 FastAPI、SSE、数据库和报告导出；公开 Pages 版本则明确是无写入的确定性演示。

### 增加 0:15｜诚实边界与商业路径

说明当前不支持浏览器 Agent、动态 LLM 红队或真实副作用执行，公开 Registry 也尚无第三方正式条目。商业交付可以从一次体检、深度修复到持续 CI 回归逐步展开，但不虚构客户与收入。
