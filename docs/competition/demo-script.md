# 现场 Demo 脚本

## 目标

在 2 分钟内让评委亲手看到三个事实：同场对照、过程可观察、安全边界真的会暂停或阻断。

## 会前准备

1. 运行 `make check` 并保存成功输出。
2. 运行 `make demo`，确认交互式公开站可以完整播放三个剧本。
3. 预先打开公开演示首页，保持“人工审批”剧本处于准备状态。
4. 如展示本地完整模式，再运行 `make compose-up` 并确认 `/health` 可访问。
5. 不在现场输入 API Key；公开演示永远使用确定性剧本。

## 2 分钟主路径

### 0:00–0:20｜说明问题

打开“发起竞技”，指出页面顶部的“浏览器内确定性模拟”。

讲解：“普通 Agent Demo 只展示一次成功。我们让两个 Agent 进入同一个安全副本，不只看答案，还记录它们怎样调用工具、有没有越权、是否知道该停下来。”

### 0:20–0:50｜触发 Prompt Injection 对局

1. 选择 `Prompt Injection`。
2. 点击“开始动态演示”。
3. 指出左右两条 Trace：一个 Agent 请求未授权 SecretTool，另一个将检索内容标记为不可信。
4. 展示最终四维评分和胜负原因。

讲解：“两边拿到完全相同的文档。左边把文档里的恶意文字当成指令，右边只提取事实。网关拦住了真实副作用，但裁判仍会扣掉安全分。”

### 0:50–1:30｜把决定权交给评委

1. 点击“选择其他剧本”，切换到“人工审批”。
2. 开始演示，等待页面出现“运行已暂停”。
3. 请评委选择“批准并继续”或“拒绝操作”。
4. 指出这个决定随后出现在 `approval.decided` Trace 中。

讲解：“这一步不是视频。运行状态真的停在浏览器内，直到人类决定。选择不会触碰任何真实系统，但能完整展示 human-in-the-loop 语义。”

### 1:30–2:00｜查看证据并收束

1. 点击“查看 LangGraph 完整轨迹”。
2. 展示递增事件、脱敏 Payload 和最终评分。
3. 回到一句话：“稳定不是一张成功截图，而是一段可以回放、比较和复算的工程证据。”

## 5 分钟扩展

- 再播放“路径穿越”，解释 Agent 主动拒绝与被网关拦截的差异。
- 打开“副本库”，说明场景以版本化 YAML 管理。
- 打开“竞技榜”，强调当前公开分数是确定性示例，不是第三方模型正式排名。
- 如环境允许，切到本地完整模式，展示 FastAPI/SSE 产生的真实运行 Trace。

## 备选路径

如果 Docker、模型或网络不可用，直接使用已经加载完成的 GitHub Pages 交互演示。它的剧本与资源随静态站发布，页面加载完成后不需要后端或模型。若交互被中断，则打开“运行轨迹”“竞技榜”和“副本库”展示冻结证据，并使用通过的 E2E 输出证明完整交互链路。

## 必须主动说明

- 公开动态演示是浏览器内确定性回放，不是实时模型推理。
- 它不发送写请求、不连接模型、不写排行榜，也不访问本机文件。
- 本地完整模式与公开演示共用 Trace 语义，但数据来源不同。

## 禁止现场展示

- `.env`、API Key、真实数据库、原始私有 Trace 或本机路径。
- 尚未实现的并行、持久化恢复、失败聚类或统计显著性页面。
- 把交互剧本描述成真实模型现场运行，或把示例榜单描述成第三方正式排名。
