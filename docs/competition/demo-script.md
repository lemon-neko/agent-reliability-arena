# 现场 Demo 脚本

## 目标

在 2 分钟内让评委看到四件事：接入对象明确、72 次测试会动态执行、严重风险会触发门禁、报告能落到可复现证据。

## 会前准备

1. 运行 `make check`。
2. 公开展示运行 `make demo`，打开 `http://127.0.0.1:4173/agent-reliability-arena/`。
3. 真实本地展示运行 `make demo-live`，确认 `http://127.0.0.1:8000/health` 正常。
4. 预先打开“新建体检”，不要在现场展示 `.env` 或任何真实凭证。

## 2 分钟主路径

### 0:00–0:20｜指出被测对象

进入“Agent 项目”，展示故意脆弱与加固两个演示 Target。

讲解：“平台评测的是你自己的 HTTP Agent。凭证只保存环境变量名称，完整结果默认留在本机。”

### 0:20–0:50｜启动 Standard

进入“新建体检”，选择“故意脆弱 Agent”和 Standard，点击“开始 72 次风险体检”。

讲解：“12 个基准会通过固定 Seed 扩展为 36 个逻辑测试，每项重复两次。页面正在动态执行，不是预录视频。”

### 0:50–1:20｜观察门禁

指向实时进度和新出现的风险：Prompt Injection、Secret 泄露、未授权工具、审批绕过。打开一条 Trace。

讲解：“Agent 只提交工具意图，平台沙箱执行并留证；所以即使它想访问元数据服务或做高影响操作，也不会触碰真实系统。”

### 1:20–1:50｜查看报告

等待 72/72 后打开“风险报告”。展示 E 级、上线建议、Critical/High 门禁、六维分数与 Finding 详情。

讲解：“平均分不会掩盖严重风险。Critical 直接把最终等级限制为 E。每项问题都有预期、实际、Trace、复现命令和修复建议。”

### 1:50–2:00｜同场对照

切换“加固 Agent”报告，展示 A 级与建议上线。

讲解：“这是同一版本测试条件下的行为差异。公开榜单还会绑定 Agent、测试包、日期和验证等级。”

## 5 分钟扩展

- 打开“项目总览”解释八类风险覆盖和 12/72/180 三档矩阵。
- 打开“执行中心”展示运行失败隔离、取消与 SSE 状态。
- 打开 HTML 报告，用浏览器打印预览说明 PDF 交付路径。
- 打开“公开基准”，说明演示条目、真实 Registry 和验证等级的区别。
- 打开“竞技场”，说明原模型/Runtime 对比能力仍然保留，但不再是主流程。

## 网络或模型失败的备选路径

直接使用已加载的 GitHub Pages Demo。演示数据和状态机随静态站发布，页面加载后不需要后端、数据库、模型或 API Key。若动画中断，可直接打开两份冻结报告和公开基准，再用通过的 Playwright E2E 结果证明 72 次流程。

## 必须主动说明

- Pages Demo 在浏览器内模拟完整 Standard 流程，所有数据都标注为演示数据。
- `make demo-live` 才会通过真实 HTTP 调用仓库内参考 Agent。
- Mock HTTP/业务工具不会访问真实外部系统。
- 分数是固定测试范围内的风险基准，不是法律、合规或绝对安全认证。

## 禁止现场展示

- `.env`、API Key、真实客户 Prompt、私有 Fixture、完整私有 Trace 或本机敏感路径。
- 把演示榜单说成第三方正式排名。
- 把浏览器打印 PDF 说成服务端签名 PDF。
- 把协作式取消、线程池并发或固定公开用例夸大为分布式调度、动态红队或统计显著性。
